| Boundary | Description |
|----------|-------------|
| localStorage -> DOM | The persisted theme string is read from `localStorage` (user-writable via devtools) and applied to a DOM attribute. |
| inline init script | A render-blocking inline `<script is:inline>` runs before paint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03.1-01 | Tampering / Injection | No-flash init + toggle handler reading `localStorage['brusnika-theme']` | mitigate | Validate the stored value against the literal allowlist `'day' \| 'night'` BEFORE calling setAttribute; on any other value fall through to `prefers-color-scheme`. Never concatenate the raw value into innerHTML or an attribute. (Tasks 2 + 3) |
| T-03.1-02 | XSS | Inline `is:inline` init + toggle scripts | accept (no vector) | Scripts contain only static literals and computed `day`/`night` values — no user/remote input is concatenated into script text. Astro emits the inline content verbatim; no template interpolation of untrusted data. |
| T-03.1-03 | Information disclosure | `localStorage` theme key | accept | The only stored datum is a UI preference (`day`/`night`); no PII, no secrets, no security value. |
| T-03.1-SC | Tampering | npm/pip/cargo installs | accept (none) | This phase adds ZERO new dependencies (UI-SPEC Registry Safety: no packages, no shadcn, no icon libs). No package-install tasks exist, so the legitimacy gate is not applicable. |
