**Mapped:** 2026-06-25
**Files analyzed:** 14 (1 created, 13 modified)
**Analogs found:** 14 / 14 (all in-codebase — this is a tokenization refactor, every analog is the file itself or a sibling)

> This phase is a CSS tokenization + theme-switching refactor, not greenfield feature work.
> The dominant pattern is: **find a hardcoded hex/rgba, replace it with `var(--token)`, define
> that token (night value) in `:root` and (day value) in `[data-theme="day"]` in `global.css`.**
> "Analogs" here are the existing token-consumption pattern (`var(--color-*)`) already present in
> the same files, plus the one true new artifact: the no-flash init script (analog = the existing
> `.js-reveal` inline script). The exact token names, night values, and day values are already
> fully specified in `03.1-UI-SPEC.md` § Complete Token Contract — the planner should treat that
> table as the canonical token list and this file as the "where each value currently lives + the
> pattern to convert it."

## Shared Patterns

These three patterns repeat across every modified component and should be applied uniformly.

### Pattern 1 — Token consumption (already established, the target shape)

**Source:** `src/styles/global.css` (lines 11-30) is the definition site; `Nav.astro` line 56 / `FooterSection.astro` line 116 are consumption sites.

The codebase already uses this exact shape for the 12 tokens that ARE tokenized:

```css
/* DEFINITION — global.css :root (night defaults) */
:root {
  --color-bg: #000;
  --color-accent: #f3a9bd;
  --color-text: #f2f0ee;
  --color-border: rgba(255, 255, 255, 0.08);
  --color-border-subtle: rgba(255, 255, 255, 0.06);
  /* ... */
}

/* CONSUMPTION — anywhere in a component */
background: var(--color-accent);
color: var(--color-text);
border-bottom: 1px solid var(--color-border-subtle);
```

**Apply to:** every new token. Add each new token name from UI-SPEC § Complete Token Contract to `:root` with its **night** value, then replace the matching hardcoded literal in the component with `var(--token-name)`. After step 1 the night theme MUST be pixel-identical (only literals → vars, no value changes).

### Pattern 2 — Day override block (NEW, but mirrors the `:root` shape exactly)

**Source pattern:** identical structure to the `:root` block above; values from UI-SPEC § Complete Token Contract "Day value" columns.

```css
/* Append to global.css AFTER :root. Same variable names, day values. */
[data-theme="day"] {
  --color-bg: #f5f0ea;            /* Direction B / Warm Cream first per UI-SPEC step 2 */
  --color-accent: #c94a6e;
  --color-text: #1a1714;
  --color-border: rgba(0, 0, 0, 0.08);
  /* ... all 12 base + ~21 new tokens ... */
}
```

CSS cascade does the rest — no component touches `[data-theme]` except the grain/glow opacity rules (Pattern 5 below).

### Pattern 3 — `::selection` and root-bg coupling

**Source:** `global.css` lines 53-56 and `Layout.astro` line 71.

`::selection` hardcodes `color: #000` (line 56) and the Layout root wrapper hardcodes `background:#000` (inline style, line 71). Both must become tokens:
- `::selection { color: var(--color-text-on-accent); }` (new token, `#000` night / `#fff` day)
- Layout root wrapper `background:#000` → `background:var(--color-bg)` (move off inline style or use `style="...background:var(--color-bg);"`)

### `src/layouts/Layout.astro` (layout/provider) — NO-FLASH INIT + ROOT BG

**Analog:** the existing `.js-reveal` inline render-blocking script (lines 59-67). The new theme-init script is a direct sibling: same `<script is:inline>` form, same "run before paint, set an attribute on `documentElement`" job.

**Existing inline init pattern to copy** (lines 59-67):
```html
<script is:inline>
  (function () {
    if (window.matchMedia && window.matchMedia('(prefers-reduced-motion: reduce)').matches) {
      return;
    }
    document.documentElement.classList.add('js-reveal');
  })();
</script>
```

**New script to add immediately after it** (exact body specified in UI-SPEC § No-Flash Init Script):
```html
<script is:inline>
  (function () {
    var saved = localStorage.getItem('brusnika-theme');
    if (saved === 'day' || saved === 'night') {
      document.documentElement.setAttribute('data-theme', saved);
      return;
    }
    var prefersDark = window.matchMedia &&
      window.matchMedia('(prefers-color-scheme: dark)').matches;
    document.documentElement.setAttribute('data-theme', prefersDark ? 'night' : 'day');
  })();
</script>
```
Must stay render-blocking (no `defer`/`async`/`type=module`) so the attribute is set before first paint — same rationale already documented in the comment at lines 51-58.

**Root wrapper hardcoded bg to tokenize** (line 71):
```html
<div style="position:relative;overflow-x:hidden;background:#000;">   <!-- → background:var(--color-bg) -->
```

**Cursor-glow markup to tokenize** (lines 73-79) — D-07 requires softer day glow:
```html
<div id="cursor-glow" style="...background:radial-gradient(circle, rgba(243,169,189,0.16), transparent 62%);..."></div>
<div style="...background:radial-gradient(70% 45% at 50% -8%, rgba(243,169,189,0.12), transparent 60%);"></div>
```
→ replace `rgba(243,169,189,0.16)` with `var(--color-glow-cursor)` and `rgba(243,169,189,0.12)` with `var(--color-glow-radial)`. (Inline `style` attributes DO resolve `var()` — confirm; if not, lift these two backgrounds into a scoped/global CSS rule keyed by id so the token applies.)

**Toggle click handler:** add a small `<script is:inline>` IIFE (same form as `demoModal()` at lines 127-233) wiring the toggle button per UI-SPEC § Toggle Persistence (read `data-theme`, flip, `setAttribute`, `localStorage.setItem('brusnika-theme', next)`, swap icon + `aria-label`/`aria-pressed`). Place it alongside the other inline IIFEs at end of `<body>`.
