## Spacing Scale

Standard 8-point scale. Declared values match existing component patterns:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon inner padding, share icon glyph offset |
| sm | 8px | Popover item gap, popover outer offset from anchor |
| md | 16px | Popover horizontal padding, share button margin from card edge |
| lg | 24px | Error state text margin, error state vertical padding |
| xl | 32px | — (not used in new elements this phase) |
| 2xl | 48px | — (not used in new elements this phase) |
| 3xl | 64px | — (not used in new elements this phase) |

Justified exceptions (multiples of 4, used as breathing-room values where the 8/16 step is too coarse):

- **12px** — popover option row vertical padding and the error-state inter-element gap.
  A multiple of 4; sits between `sm` (8px) and `lg` (24px). Same justified exception as
  the existing 12px card slot inset already in `VideoSection.astro`.
- **44×44px touch target** for the share button (per-card `.video-share-slot` and
  modal). This is a mandatory minimum touch target, not a spacing token — same
  convention as the existing `video-modal-close` and `video-arrow` buttons. Source: CONTEXT.md D-03.
- **12px** card slot inset (`bottom: 12px; right: 12px`) — inherited verbatim from the
  `.video-share-slot` CSS already written in Phase 2. Do not change.

No spacing value anywhere in this contract is a non-multiple-of-4 (all values are drawn
from {4, 8, 12, 16, 24, 32, 48, 64}).

## Interaction Contracts

### Share Flow (Mobile — Web Share API with file)

1. User taps share button on a clip card or inside the enlarge modal.
2. JS calls `navigator.canShare({ files: [mp4File] })`.
   - If true: fetch the clip `.mp4` from the CDN URL (`data-clip-url`), construct a `File` object, call `navigator.share({ files: [file], title: clipTitle, text: shareText, url: siteUrl })`.
   - If false (files not supported): fall back to `navigator.share({ title: clipTitle, text: shareText, url: siteUrl })` (link share only — no popover).
3. If `navigator.share` itself is absent (no Web Share API): show the desktop popover (see below).
4. Errors from `navigator.share` that are NOT `AbortError` (user cancelled) must not surface any UI — silently ignored (user cancelled is intentional, not a failure).

### Share Flow (Desktop — popover)

1. User clicks share button.
2. Popover opens (`data-open="true"`, `visibility:visible`).
3. Click on VK or Telegram option → opens platform share URL in new tab; popover closes.
4. Click on "Скопировать ссылку" → clipboard write → inline "Скопировано ✓" for 2s; popover stays open until click-outside or Esc.
5. Click outside popover or press Esc → popover closes (`data-open="false"`, `visibility:hidden`).

### Booking Submit Flow

1. User clicks "отправить заявку" (`#lessons-form` submit).
2. JS reads four visible form fields (format, name, contact, experience) + checks honeypot.
   - If honeypot filled: silently return HTTP 200 (do not error, do not deliver — bot trap).
3. `fetch('/api/book', { method: 'POST', body: FormData })`.
4. **Success** (HTTP 200 from endpoint, meaning Telegram delivered): hide `#lessons-form`, show `#lessons-thanks`. "Спасибо!" state. Existing markup — no changes.
5. **Failure** (HTTP 4xx/5xx, network error, or timeout): hide `#lessons-form`, show `#lessons-error`. The error state shows the heading + body + direct Telegram link + retry link.
6. "Попробовать снова" in error state: hide `#lessons-error`, show `#lessons-form` again (reset values retained — do not clear the form).
7. Rate-limit response (HTTP 429): same error state — no special UI beyond the generic error; rate-limiting is invisible to the user (no countdown).
8. Submit button loading state: during fetch, button shows "отправляем..." (same button, text only) and `disabled` attribute. On resolve or reject, disabled is removed.

**Share text (D-07):**

```
title: "{clipTitle} — внимание брусника!"
text: "внимание брусника! — слушайте и смотрите"
url: site canonical URL (window.location.origin)
```

No hashtag (D-08). URL is home page only (D-09). Exact wording editable in `site.ts`.

## Implementation Notes for Executor

1. **Inert-when-closed pattern is mandatory.** The share popover must use `pointer-events:none` + `visibility:hidden` when closed (not `opacity:0` alone). See accumulated context note: "Closed overlays must be inert via pointer-events:none + visibility:hidden (not just opacity:0)."

2. **Portal the share popover to `<body>`.** Like the video modal and lessons modal, the share popover (if it could be clipped by `overflow:hidden` on a parent) must be appended to `<body>` at runtime so it escapes any stacking context set by the `.video-card` or `.video-frame`. Set `z-index: 2010` (above video modal 2000).

3. **Standard bundled `<script>` for share logic** (not `is:inline`) if the share script imports any asset. If share logic is purely vanilla JS with no imports, either pattern is acceptable — but prefer the standard bundled block for consistency.

4. **The lessons modal submit handler is `is:inline` in `Layout.astro`.** The submit handler replacement (`demo-modal.js` lines 69–77) stays in that inline block per Phase 2 D-05 isolation contract. Do NOT move it to a separate bundled script.

5. **`data-clip-url` and `data-clip-title`** are already on each `.video-card` element. The share button JS reads these; no new data attributes needed on cards.

6. **File fetch for mobile share.** The clip `.mp4` URL comes from `data-clip-url`. Fetch it as `blob`, construct `new File([blob], filename, { type: 'video/mp4' })`, then pass to `navigator.share({ files: [...] })`. Guard with `navigator.canShare({ files: [file] })` before fetching (avoid a full CDN fetch on devices that can't use it).

7. **Rate-limiting.** The `/api/book.ts` endpoint must track IP-based request count (5 requests per 60 seconds → HTTP 429). Vercel serverless instances are ephemeral — use an in-memory Map (acceptable for v1 low traffic; not shared across instances, which is a known limitation, not a bug). A shared store (KV/Redis) is a v2 concern.

8. **Email channel is built but gated off.** The `/api/book.ts` endpoint should have the email send path implemented but wrapped in `if (process.env.EMAIL_ENABLED === 'true')`. The env var defaults to absent (falsy) — email does nothing unless explicitly enabled. No dead placeholder address.

9. **`TELEGRAM_BOT_TOKEN` has no `PUBLIC_` prefix.** Server-side only. Never reference it in any client-side code, `<script>` block, or component prop.
