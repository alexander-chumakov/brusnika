## Token Architecture

### Mechanism

Use a `data-theme` attribute on `<html>`. The `:root` block in `global.css`
defines night (dark) tokens as defaults. A `[data-theme="day"]` override block
redefines the same variable names for the light palette.

```css
/* global.css — existing night defaults stay unchanged */
:root {
  --color-bg: #000;
  /* … 11 more tokens … */
}

/* Day override — same names, day values */
[data-theme="day"] {
  --color-bg: <day value>;
  /* … same 11 names … */
}
```

This approach: zero JS framework dependency; no class pollution on body; one
attribute read in the no-flash script; CSS cascade handles everything.

### No-Flash Init Script

Inline render-blocking `<script is:inline>` in `<head>` of `Layout.astro`,
placed immediately after the existing `.js-reveal` script. It runs before first
paint and sets `data-theme` on `<html>`:

```js
(function () {
  var saved = localStorage.getItem('brusnika-theme');
  if (saved === 'day' || saved === 'night') {
    document.documentElement.setAttribute('data-theme', saved);
    return;
  }
  // No explicit choice — follow system preference
  var prefersDark = window.matchMedia &&
    window.matchMedia('(prefers-color-scheme: dark)').matches;
  document.documentElement.setAttribute('data-theme', prefersDark ? 'night' : 'day');
})();
```

The localStorage key is `brusnika-theme`. Values: `'day'` | `'night'`. The
no-flash init ALWAYS sets an explicit `data-theme` (`'night'` or `'day'`) — it
never leaves the attribute absent. (The user's mockup used the key `vb-theme`
and treated night as "no attribute"; we deliberately do NOT adopt those — our
key stays `brusnika-theme` and night is the explicit value `'night'`.)

### Toggle Persistence

On toggle click:
1. Read current `data-theme` from `document.documentElement`.
2. Compute next value (`'day'` → `'night'`, `'night'` → `'day'`).
3. Set `document.documentElement.setAttribute('data-theme', next)`.
4. `localStorage.setItem('brusnika-theme', next)`.
5. Play the eye-blink animation (see "Toggle Control" → "Form (locked): brand
   eye with eyelashes") and update `aria-label` + `aria-pressed`.

### Transition on Toggle

CSS on `html` element:
```css
html {
  transition:
    background-color 0.25s ease,
    color 0.25s ease;
}
```

Individual surfaces (cards, player bar, modals) also carry `transition:
background-color 0.25s ease, border-color 0.25s ease` so the switch feels
fluid, not jumpy. **Do not** transition opacity or transform during theme swap
(conflicts with scroll-reveal animations).

## Day Palette — Warm Cream (LOCKED, D-01 / D-02)

The day palette is no longer a prototype-two-and-pick step. The user's generated
mockup (`Внимание Брусника-2.html`) settled it: **Warm Cream / Paper**. The
"Clean White" alternative is removed.

Concept: the physical world of cassette tapes, tour flyers, rehearsal studio
walls. Warm off-white with a slight parchment/ochre pull. Film grain reads as
analog texture on this palette instead of noise — the best fit for the dream-pop
mood. The accent pink deepens to `#c95572` (rgb 201,85,114) for contrast on the
warm background; night keeps `#f3a9bd` unchanged.

| Role | Hex | Notes |
|------|-----|-------|
| Page background | `#f7f4ef` | Warm off-white, slight parchment (mockup `--color-bg`) |
| Raised surface | `#efeae1` | Slightly darker warm cream (mockup `--color-bg-raised`) |
| Modal background | `#f3eee6` | Modal matches warm page bg (derived) |
| Text primary | `#231d1a` | Warm near-black (mockup `--color-text`) |
| Text muted | `#675f57` | Warm readable grey (mockup `--color-text-muted`) |
| Day accent | `#c95572` | Deep warm pink — works on cream (mockup `--color-accent`) |
| Day accent hover | `#a83f5c` | Darker on hover (derived from accent rgb) |

All accent-derived day rgba tokens (`--color-accent-tint`, `-tint-strong`,
`-ring`, `-ticket`, `-ticket-border`, `--color-glow-cursor`,
`--color-glow-radial`, `--color-surface-player-border`) are recomputed from the
day accent rgb **201,85,114**, keeping the alpha values from the contract table
above.

## Film Grain + Cursor Glow in Day Mode (D-07)

Per D-07, keep both effects but reduce intensity.

### Film Grain

Night: full opacity. Day: reduce grain overlay opacity from 1 to 0.4.

Add a token or direct rule on `[data-theme="day"]` for the grain element:
```css
[data-theme="day"] .grain {
  opacity: 0.4;
}
```
(Use whatever class/selector the existing grain overlay uses.)

### Cursor-Follow Glow

Night: `rgba(243,169,189,0.16)` inner glow + `rgba(243,169,189,0.12)` top
radial. Day: `rgba(201,85,114,0.07)` inner + `rgba(201,85,114,0.05)` top
radial. Both tokenized via `--color-glow-cursor` and `--color-glow-radial`
above. The glow still shows on fine-pointer devices only (existing behavior).

## Toggle Control

### Placement (D-03)

Top-right corner of the nav bar. On desktop: sits to the right of the nav link
group. On mobile (nav menu hidden): visible in the top-right position as the
only nav control shown.

Nav layout adjustment: add a slot after the nav links for the toggle. Width
budget: 40px × 40px touch target.

### Form (LOCKED, D-04): brand eye with eyelashes

The toggle icon is **the брусника brand eye with eyelashes** (`глаз с
ресничками`). It is NOT sun/moon and NOT the lingonberry. This is settled — no
icon-variant prototyping.

- A single round 40×40 button in the top-right of the nav (D-03) containing the
  eye icon (~20px viewBox inside).
- The icon uses `currentColor`-friendly markup so `var(--color-text-muted)` at
  rest / `var(--color-text)` on hover apply (same as the rest of the spec).
- The same eye shows in both themes (it is the brand mark, not a state
  indicator). State is conveyed via `aria-pressed` + `aria-label` text, not by
  swapping artwork.

#### Blink animation (on toggle)

On click the eye plays a short **blink**:

- CSS `@keyframes` of roughly **0.36s** (scaleY the eyelid/iris closed→open, or
  equivalent). The class name is `blink` on the eye element.
- Trigger pattern (from the mockup): `el.classList.remove('blink')` → force
  reflow `void el.offsetWidth` → `el.classList.add('blink')`. This restarts the
  animation on every click.
- **Respect `prefers-reduced-motion: reduce`:** when reduced motion is
  requested, SKIP the blink (and the optional reveal below).

#### Asset reality — [BLOCKING]

The actual eye artwork is **not available yet**. The mockup referenced it by a
broken UUID `<img src>`; nothing is embedded. Spec the asset at
`public/icons/theme-eye.svg`.

- If the user has dropped a real eye artwork into `public/icons/theme-eye.svg`,
  use it.
- OTHERWISE the executor MUST author a clean inline SVG **eye with eyelashes**
  as a fallback so the toggle is never broken. Do not ship a broken `<img>`.

#### Optional enhancement — circular view-transition reveal

OPTIONAL (not required; must not block verification). Gated on BOTH
`document.startViewTransition` support AND not `prefers-reduced-motion: reduce`:
on theme change, animate a circular `clip-path` reveal emanating from the toggle
button center (as in the mockup — `circle(0px at x y)` → `circle(end at x y)`,
~620ms, `cubic-bezier(.16,.7,.2,1)` on `::view-transition-new(root)`). If
unsupported or reduced-motion, just apply the theme directly. Mark explicitly
optional in the plan so it can never gate the checkpoint.

## Implementation Order (for Planner)

The executor should tackle in this order to minimize merge conflicts:

1. **Token extraction** — Add all new CSS custom properties to `:root` in
   `global.css` using current (night) hex values. No visual change yet.
   Touch the ~92 hardcoded values across all components and replace with
   `var(--token-name)`. Verify night theme is pixel-identical after.

   with the locked **Warm Cream** values from the Complete Token Contract.

   that hard refresh + `prefers-color-scheme` sets the right theme with zero

   blink the eye (respecting reduced-motion), update aria.

6. **Eye asset finalize + human confirm (Plan 04)** — Ensure
