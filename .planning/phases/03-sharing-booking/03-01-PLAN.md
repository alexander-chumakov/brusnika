Wire a `shareClip(clipUrl, clipTitle)` handler invoked by every `.video-share-btn` click. Card buttons read url/title via `btn.closest('.video-card')?.dataset.clipUrl` / `.clipTitle`; the modal button reads the currently-open clip (store it when the modal opens). Flow (RESEARCH Pattern 5, honoring iOS caveat):
1. Compute `siteUrl = window.location.origin` (D-09 — home page, runtime only).
2. If `navigator.canShare` and `navigator.canShare({ files: [new File([''], 'test.mp4', { type:'video/mp4' })] })` → `fetch(clipUrl)` → `blob()` → `new File([blob], \`${clipTitle}.mp4\`, { type:'video/mp4' })` → `await navigator.share({ files:[file] })` with FILES ONLY (no title/text/url — iOS Safari suppresses the sheet otherwise, RESEARCH Pitfall 2). On AbortError return silently; on other error fall through.
3. Else if `navigator.share` exists → `await navigator.share({ title: shareTitle(clipTitle), text: shareText, url: siteUrl })` (link share). AbortError → silent.
4. Else (no Web Share API → desktop) → open `.share-popover`: position it `position:fixed` near the clicked button (anchor via getBoundingClientRect), set `data-open="true"` after a reflow, set the button's `aria-expanded="true"`.

Popover behaviour: VK row → `window.open('https://vk.com/share.php?url=' + encodeURIComponent(siteUrl), '_blank', 'noopener')` then close popover; Telegram row → `window.open('https://t.me/share/url?url=' + encodeURIComponent(siteUrl) + '&text=' + encodeURIComponent(shareText), '_blank', 'noopener')` then close; Copy row → `navigator.clipboard.writeText(siteUrl)` then swap the label to «Скопировано ✓» (add `.share-copied`) for 2000ms, revert, keep popover open. Close popover on click-outside and on Escape (reuse the existing keydown pattern); on close set `data-open="false"` and `aria-expanded="false"` and return focus to the triggering button. Any `navigator.share` rejection that is NOT AbortError must surface no error UI (silent).

Do not reference `process.env`, secrets, or any server value in this client script.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → CDN (Vercel Blob) | Client `fetch(clipUrl)` to turn the clip into a Blob for the share sheet crosses origins; requires CDN CORS |
| browser → platform share URLs (VK/Telegram) | Outbound `window.open` to third-party share endpoints with the public home URL only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03S-01 | Information Disclosure | share JS client bundle | mitigate | No secrets in client code; share script references only public data (clip URLs, public home URL); acceptance grep confirms no TELEGRAM_BOT_TOKEN/process.env in VideoSection.astro |
| T-03S-02 | Denial of Service | CDN fetch-to-blob | accept | A user can only fetch publicly-served clip files to their own browser; no amplification; CORS is a config concern flagged for Phase 4 verification, not a security exposure |
| T-03S-03 | Tampering | share URL construction | mitigate | All user-visible share params are `encodeURIComponent`-escaped; only `window.location.origin` and the fixed Russian shareText are sent — no user input is interpolated into share URLs |
| T-03S-SC | Tampering | npm installs | mitigate | This plan installs NO packages (uses browser built-ins only); no slopcheck checkpoint needed for Plan 01 |
</threat_model>
