## Token Architecture

### Mechanism

Use a `data-theme` attribute on `<html>`. The `:root` block in `global.css`
defines night (dark) tokens as defaults. A `[data-theme="day"]` override block
redefines the same variable names for the light palette.

```css
/* global.css — existing night defaults stay unchanged */
:root {
  --color-bg: #000;
  /* … 11 more tokens … */
}

/* Day override — same names, day values */
[data-theme="day"] {
  --color-bg: <day value>;
  /* … same 11 names … */
}
```

This approach: zero JS framework dependency; no class pollution on body; one
attribute read in the no-flash script; CSS cascade handles everything.

### No-Flash Init Script

Inline render-blocking `<script is:inline>` in `<head>` of `Layout.astro`,
placed immediately after the existing `.js-reveal` script. It runs before first
paint and sets `data-theme` on `<html>`:

```js
(function () {
  var saved = localStorage.getItem('brusnika-theme');
  if (saved === 'day' || saved === 'night') {
    document.documentElement.setAttribute('data-theme', saved);
    return;
  }
  // No explicit choice — follow system preference
  var prefersDark = window.matchMedia &&
    window.matchMedia('(prefers-color-scheme: dark)').matches;
  document.documentElement.setAttribute('data-theme', prefersDark ? 'night' : 'day');
})();
```

The localStorage key is `brusnika-theme`. Values: `'day'` | `'night'`.

### Toggle Persistence

On toggle click:
1. Read current `data-theme` from `document.documentElement`.
2. Compute next value (`'day'` → `'night'`, `'night'` → `'day'`).
3. Set `document.documentElement.setAttribute('data-theme', next)`.
4. `localStorage.setItem('brusnika-theme', next)`.
5. Swap icon (sun↔moon or lingonberry day↔night variant).

### Transition on Toggle

CSS on `html` element:
```css
html {
  transition:
    background-color 0.25s ease,
    color 0.25s ease;
}
```

Individual surfaces (cards, player bar, modals) also carry `transition:
background-color 0.25s ease, border-color 0.25s ease` so the switch feels
fluid, not jumpy. **Do not** transition opacity or transform during theme swap
(conflicts with scroll-reveal animations).

## Day Palette — Two Directions (Prototype Both)

Per D-01, the executor MUST implement both directions as prototypable states so
the user can toggle between them and pick by sight. Implement as a second toggle
or side-by-side screenshot step — not a permanent runtime option.

### Direction A — Clean White

Concept: airy, modern, gallery-white. Cool neutrals. The accent pink deepens to
`#c94a6e` for contrast.

| Role | Hex | Notes |
|------|-----|-------|
| Page background | `#ffffff` | Pure white |
| Raised surface | `#f8f8f8` | Off-white cards, nav when scrolled |
| Modal background | `#ffffff` | Matching page bg for clean continuity |
| Text primary | `#1a1714` | Near-black with warm undertone |
| Text muted | `#4a4642` | Dark grey, readable at 16px |
| Day accent | `#c94a6e` | Saturated deep pink — high contrast on white |
| Day accent hover | `#a83057` | Darker on hover |

### Direction B — Warm Cream / Paper (Claude's Recommendation)

Concept: the physical world of cassette tapes, tour flyers, rehearsal studio
walls. Warm off-white with slight yellow-ochre pull. Film grain reads as analog
texture on this palette instead of noise. Best fit for dream-pop mood.

| Role | Hex | Notes |
|------|-----|-------|
| Page background | `#f5f0ea` | Warm off-white, slight parchment |
| Raised surface | `#ede8e0` | Slightly darker warm cream |
| Modal background | `#f0ebe3` | Modal matches warm page bg |
| Text primary | `#1a1714` | Same near-black as Direction A |
| Text muted | `#4a4642` | Same readable grey |
| Day accent | `#c94a6e` | Same deep pink — works on cream too |
| Day accent hover | `#a83057` | Consistent with Direction A |

Both directions share the same accent (`#c94a6e`) so the button components and
interactive states require only one tokenization pass.

## Film Grain + Cursor Glow in Day Mode (D-07)

Per D-07, keep both effects but reduce intensity.

### Film Grain

Night: full opacity. Day: reduce grain overlay opacity from 1 to 0.4.

Add a token or direct rule on `[data-theme="day"]` for the grain element:
```css
[data-theme="day"] .grain {
  opacity: 0.4;
}
```
(Use whatever class/selector the existing grain overlay uses.)

### Cursor-Follow Glow

Night: `rgba(243,169,189,0.16)` inner glow + `rgba(243,169,189,0.12)` top
radial. Day: `rgba(201,74,110,0.08)` inner + `rgba(201,74,110,0.06)` top
radial. Both tokenized via `--color-glow-cursor` and `--color-glow-radial`
above. The glow still shows on fine-pointer devices only (existing behavior).

## Toggle Control

### Placement (D-03)

Top-right corner of the nav bar. On desktop: sits to the right of the nav link
group. On mobile (nav menu hidden): visible in the top-right position as the
only nav control shown.

Nav layout adjustment: add a slot after the nav links for the toggle. Width
budget: 40px × 40px touch target.

### Form — Two Variants to Prototype (D-04)

**Variant 1 — Sun/Moon (safe fallback)**

- Night mode shows: crescent moon SVG icon
- Day mode shows: sun with rays SVG icon
- Icon size: 20px × 20px inside a 40px × 40px button
- Icon color: `var(--color-text-muted)` at rest, `var(--color-text)` on hover
- No label text — icon alone (both are universally understood)
- `aria-label`: `"Переключить на дневную тему"` / `"Переключить на ночную тему"`

**Variant 2 — Брусника brand icon**

- Night mode shows: lingonberry/sprig icon with subtle night glow
- Day mode shows: same sprig with a sun-washed / bright treatment (lighter
  berry fill, no glow)
- Same 40px × 40px button, 20px icon
- Design the icon as a single path SVG; swap fill between night/day via CSS
  on `[data-theme]`

**Implementation instruction:** prototype Variant 1 first (SVG is trivial).
Variant 2 requires a custom SVG asset — create it as `public/icons/brusnika-
toggle-night.svg` and `public/icons/brusnika-toggle-day.svg`. Use inline `<img>`
or inline SVG `<svg>`. The user picks the variant by sight.

### Button Spec

```
button
  width: 40px
  height: 40px
  border-radius: 50%
  border: 1px solid var(--color-border)
  background: transparent
  cursor: pointer
  display: flex

  justify-content: center
  transition: background 0.2s ease, border-color 0.2s ease
  
button:hover
  background: var(--color-accent-tint)
```

## Implementation Order (for Planner)

The executor should tackle in this order to minimize merge conflicts:

1. **Token extraction** — Add all new CSS custom properties to `:root` in
   `global.css` using current (night) hex values. No visual change yet.
   Touch the ~92 hardcoded values across all components and replace with
   `var(--token-name)`. Verify night theme is pixel-identical after.

2. **Day palette block** — Add `[data-theme="day"]` block to `global.css`
   with Direction B (Warm Cream) values first (easier to see contrast
   differences than pure white against white). After user confirms visual
   pick, update to chosen direction.

3. **No-flash init script** — Add inline `<script is:inline>` in
   `Layout.astro` `<head>` (after the existing `.js-reveal` script). Test
   that hard refresh + `prefers-color-scheme` sets the right theme with zero
   flash.

4. **Toggle control** — Add toggle button to `Nav.astro`. Wire click handler
   inline (or in a bundled `<script>`). Implement Variant 1 (sun/moon) first.

5. **Glow / grain softening** — Apply day-mode opacity rules for the grain
   overlay and update cursor glow to use the new tokens.

6. **Day prototype B** — Developer screenshots or side-by-side deploy for user
   to pick palette direction. After pick, commit Direction A or B as the
   permanent day palette.

7. **Variant 2 icon (optional)** — Create lingonberry SVG, wire up, present
   to user as toggle icon alternative.
